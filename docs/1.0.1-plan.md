## 2. imgUploader: merge it or keep it separate?

### What it is
A resumable bulk uploader. It scans the `directories` from a pixBoards config, writes a
`manifest.yml` job list of leaf folders, uploads each folder to imgchest in posts of up to 20
images, records the posts and fills the **same `image_cache` table** pixBoards reads.

### Problems found in it
- **Reads its config at import time**, from a hardcoded absolute Windows path to a pixBoards
  config file.
- **Connection code is broken or hardcoded:**
  - `connect_aiven()` uses an undefined `aiven_host` and placeholder port/password;
  - `connect_db()` hardcodes the credentials.
- **`arguments.py` calls `logger` without importing it.** If `IMG_CHEST_API_KEY` is missing, it
  crashes with `NameError`.
- **`schema.sql` and `db.py` disagree:** `imgchest_posts.sequence` exists only in `db.py`, and
  `gallery_posts` exists only in `schema.sql` and is never used.
- **Only leaf folders are uploaded** (`media and not dirs`). A folder that has both images and
  subfolders is skipped entirely.
- **The transaction covers a whole folder, while imgchest posts are created every 20 images.**
  If batch 3 of 5 fails, the rollback discards the records of posts 1 and 2. They stay on imgchest
  as orphans and are uploaded again next run.
- **Links are matched to files by position.** Only the count is checked, so a reordering by the
  API would silently attach wrong links.
- **Each 20-file batch is read fully into memory** (`f.read()`). Large videos make this heavy.
- **Unused or duplicate code:**
  - `uploaders/coordinator.py` (different `upload_folder_to_imgchest` signature, unused);
  - the Catbox fallback (not called from `main`);
  - `uploader_v2.py` (a full second copy of the uploader);
  - `misc/` (old versions).
- **`__pycache__/*.pyc` files are committed.**

### Recommendation: merge the shared parts into pixBoards, keep bulk upload as its own command

Keeping two separate repos is not the clean option here, because **both write the same table and
the schema has already drifted**. There are now four definitions of `image_cache`:
- `pixBoards/imgchest.py`
- `imgUploader/uploader/db.py`
- `imgUploader/uploader_v2.py`
- `scripts/sync_online.py`

They differ in columns (`uploaded_at`), indexes (filename index) and upsert policy (keep the old
link vs overwrite it). One owner for the schema fixes that.

On the other hand, generating HTML and bulk uploading are different jobs. Pasting the uploader
into `boardmakers.py` would make things worse. So merge it as a separate layer:

```
pixBoards/
├─ storage/              one place for all SQL
│  ├─ schema.sql
│  ├─ db.py              connect(config), migrate(conn)
│  └─ image_cache.py     lookup_many(hashes), save_links(rows), save_post(...)
├─ hosts/
│  └─ imgchest.py        upload_post(title, paths) -> post_id, links   (<= 20 files)
├─ upload/
│  ├─ scan.py            folders -> files (all folders, not only leaves)
│  └─ bulk.py            resumable bulk upload, job state in the DB
├─ ...existing board/HTML modules
```

- `pixboards --upload` (per-board) and a new `pixboards-upload` console script (bulk) both use
  `storage/` and `hosts/`.
- Both read the same `config.yml`, so the hardcoded config path goes away.
- Bulk upload is the better uploader: 20 images per post instead of pixBoards' one post per
  image, batch hash lookups, timeouts and MIME types. pixBoards' `--upload` should reuse it
  rather than keep its own `upload_image`.
- Move `scripts/sync_online.py` into this layer too (`pixboards-upload --sync`), or drop it in favour of
  pointing `config.yml` at the hosted database.
- Don't port Catbox, gofile, `uploader_v2.py` or `misc/`. Add other hosts later behind the
  `hosts/` interface if they're needed.
- Archive the imgUploader repo once `pixboards-upload` works, with a readme pointing to it.

### Alternative if you want to keep them separate
Make imgUploader depend on pixBoards (`pip install pixboards[upload]`) and import
`pixBoards.storage` for every SQL statement, so there's still only one schema. That's acceptable,
but the merged version is simpler to maintain alone.

## 3. Database: comparison and recommended changes

### Current schemas

| | pixBoards | imgUploader |
|---|---|---|
| Cache table | `{tableName}` (configurable, default `image_cache`): `hash` PK, `link`, `filename`, `uploaded_at` | `public.image_cache` (hardcoded): same columns |
| Indexes | none besides PK; lookups by `link` (sidecar) do a full scan | `filename` index |
| Post tracking | none: **one imgchest post per image** | `imgchest_posts(post_id PK, folder_path, sequence, image_count, uploaded_at)` |
| Image → post link | n/a | none (can't tell which post an image is in) |
| Existence check | one `SELECT` per file | one `= ANY(%s)` per folder |
| Upsert on re-upload | `ON CONFLICT DO NOTHING` (keeps old link) | `link = EXCLUDED.link` (overwrites) |
| Filename handling | written once, lookups by filename disabled | duplicate filenames stored as `NULL`, reported |
| Transactions | one commit per folder, **no rollback** on error | one commit per folder with rollback (but see orphaned posts) |
| DDL each run | `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN` | `CREATE TABLE/INDEX IF NOT EXISTS` |
| Board metadata | `savedBoards`: new row every run, no unique key | n/a |
| Credentials | from config | hardcoded |

**Verdict:** imgUploader's database side is better overall. It does batch lookups, has the filename
index, tracks posts, rolls back on failure and groups 20 images per post.

pixBoards' strengths are smaller:
- the table name is configurable;
- credentials come from config;
- the "keep the existing link" policy is safer, because boards that are already published keep
  working links.

Neither has migrations, a link from image to post, or a way to avoid re-hashing every file every run.

### Recommended schema (one file, `pixBoards/storage/schema.sql`)

```sql
CREATE TABLE IF NOT EXISTS schema_version (
    version    INTEGER PRIMARY KEY,
    applied_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS imgchest_posts (
    post_id     TEXT PRIMARY KEY,
    folder_path TEXT NOT NULL,
    sequence    INTEGER NOT NULL DEFAULT 1,      -- nth post for this folder
    image_count INTEGER NOT NULL,
    uploaded_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (folder_path, sequence)
);

CREATE TABLE IF NOT EXISTS image_cache (
    hash        TEXT PRIMARY KEY,                -- md5 of file contents
    link        TEXT NOT NULL UNIQUE,
    filename    TEXT,                            -- informational, not an identity
    post_id     TEXT REFERENCES imgchest_posts(post_id),
    host        TEXT NOT NULL DEFAULT 'imgchest',
    uploaded_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_image_cache_filename ON image_cache (filename);
CREATE INDEX IF NOT EXISTS idx_image_cache_post     ON image_cache (post_id);

-- skip re-hashing unchanged files (hash lookups become path+size+mtime lookups)
CREATE TABLE IF NOT EXISTS file_index (
    path  TEXT PRIMARY KEY,
    size  BIGINT NOT NULL,
    mtime DOUBLE PRECISION NOT NULL,
    hash  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_file_index_hash ON file_index (hash);

-- replaces savedBoards: one row per board, updated each run
CREATE TABLE IF NOT EXISTS boards (
    output_dir TEXT NOT NULL,
    name       TEXT NOT NULL,
    num_images INTEGER NOT NULL,
    children   TEXT[] NOT NULL DEFAULT '{}',
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (output_dir, name)
);
```

**Migrating the existing tables**
- `ALTER TABLE image_cache ADD COLUMN IF NOT EXISTS post_id TEXT, ADD COLUMN IF NOT EXISTS host TEXT NOT NULL DEFAULT 'imgchest'`.
- Add `UNIQUE (link)` only after checking for duplicates:
  `SELECT link, count(*) FROM image_cache GROUP BY link HAVING count(*) > 1`.
- Backfill `imgchest_posts.sequence` with 1 where it's missing.
- Copy `savedBoards` into `boards` (latest row per name) and drop it.
- Record each step in `schema_version` so it runs once. This replaces the `ALTER` that currently
  runs on every pixBoards start.

### Code changes for the database side
1. **One module owns all SQL** (`storage/`). Nothing else calls `cursor.execute`.
2. **Table name** through `psycopg2.sql.Identifier(config["tableName"])`, not f-strings.
3. **Connections** from config or env only. Support a `DATABASE_URL` / `sslmode` option for the
   hosted (Aiven) database instead of separate hardcoded `connect_aiven()` functions. No credentials in code.
4. **Transactions match external side effects**: commit after each imgchest post, which is the
   unit that can't be undone. `with conn:` blocks give rollback on error automatically. This fixes
   both the orphaned-posts problem and pixBoards' aborted-transaction bug.
5. **Batch everything**:
   - existence checks with `WHERE hash = ANY(%s)`;
   - inserts with `psycopg2.extras.execute_values`;
   - one round trip per folder, not per file.
6. **One upsert policy**: `ON CONFLICT (hash) DO UPDATE SET filename = COALESCE(image_cache.filename,
   EXCLUDED.filename), post_id = COALESCE(image_cache.post_id, EXCLUDED.post_id)`. Keep the existing
   link unless a `--refresh-links` option is used.
7. **Don't use filename as an identity.** Stop writing `NULL` for duplicate filenames. Keep the
   real path in `file_index`; `filename` stays informational.
8. **Hash cache**: look up `file_index` by `(path, size, mtime)` before hashing. On large
   libraries this removes most of the per-run cost.
9. **Job state in the database** instead of a 500 KB `manifest.yml` rewritten after every batch.
   A folder is done when all its file hashes exist in `image_cache`, so a re-run naturally resumes.
10. **Sync**: if the hosted database stays, sync incrementally (`WHERE uploaded_at > last_sync`)
    and include `imgchest_posts`. Better still, point `config.yml` at the hosted database and drop the sync step.

## 4. Suggested order

1. **1.0.1**: section 1 "Before releasing" (real DB test, configs, release).
2. **1.1**: `storage/` + `hosts/` with the new schema and migrations (section 3), and `pixboards --upload` switched to 20-per-post uploads. The local media cache (`pixBoards/mediacache.py`) already provides the hash cache that section 3's `file_index` table describes, so that table can be dropped from the schema.
3. **1.2**: `pixboards-upload` bulk command (section 2); archive imgUploader.
