# pixBoards 1.0.1: review and change report

Code review of pixBoards 0.2.33 and the changes made for 1.0.1 (November 2026).
The open work is in [1.0.1-plan.md](1.0.1-plan.md).

## Summary

- The biggest structural problem was **work done at import time**. Parsing `sys.argv`, reading
  `config.yml`, calling `exit()` and pushing to git all happened when a module was imported. Most of
  the bugs below came from that.
- 1.0.1 moves all of it into `cli.main(argv=None)`. Settings now travel as parameters (`config`
  dict plus flags).
- Six bugs are fixed: config overwrite, `NameError`, empty hash map, broken Linux paths, missing
  dependency and token leak.
- A **Random Page** button is now at the top of every multi-page board.
- The version is read from `pixBoards/__init__.py` by `setup.py` instead of being rewritten by it.

## What changed in 1.0.1

### Structure
- `arguments.py`: `build_parser()` / `parse_args(argv)`; nothing runs on import.
- `config_loader.py`: `build_config(args)` returns the config with CLI overrides plus derived
  `masterDir` / `outputDir`. `load_config` raises `ConfigError`. `make_config` never overwrites.
- `cli.py`: `main(argv=None)` returns an exit code. It sets up logging, loads config, owns the DB
  connection (closed in `finally`), builds boards and runs `--gitPush`. `__main__.py` calls
  `sys.exit(main())`.
- `boardmakers.py`, `create.py`, `filemaking.py`, `imgchest.py`, `classes.py` take `config` and
  flags as parameters. `board.paginate_board(imgs_per_page, padding)`.
- `imgchest.py`: API key read lazily; `process_images(paths, conn, table_name, use_sidecar, use_saved)`.
- `db.py`: `create_conn(config)` with a lazy `psycopg2` import.
- `git.py`: `push_output(config)`. The token is read from `GITHUB_PAT` and never placed in the URL or argv.
- `log_utils.py`: `setup_logging()` configures the `pixBoards` logger once; modules use `logging.getLogger(__name__)`.

### Features
- **Random Page button** at the top of each board page, below the image counts and above the
  divider (only when the board has more than one page). It never picks the current page. The
  pagination bar's button now uses the same `goToRandomPage()` function in `template.js`, replacing
  the inline JS that `create.py` used to build.

### Packaging
- Version **1.0.1**, single source in `pixBoards/__init__.py`.
- `setup.py`: reads the version, `python_requires=">=3.9"`, description/url, packages limited to
  `pixBoards*`, release notes upload only the current version's files.
- `requirements.txt`: Jinja2, Pillow, psycopg2-binary, python-dotenv, PyYAML, requests.
- `.gitattributes`: `* text=auto`, CRLF for `.bat`/`.cmd`, binaries marked.

### Docs
- `README.md`: task list.
- `CLAUDE.md` (git-ignored): notes for Claude Code.

## Cleanup pass

- Archived to `archive/` (git-ignored): Windows `.bat`/`.ps1` files (including `batchFIles/`), old
  cProfile output, build artifacts (`build/`, `dist/`, egg-info), root-level run logs, `todo.md`,
  `setup.cfg`, `countLines.py`, `main.py`, generated image lists, `templates/__init__.py.bak`.
- Removed: `gui.py`, `fib_tabbing.py` (both remain in git history).
- Moved to `scripts/`: `sync_online.py`, `picsum_generator.py`.
- New: `scripts/publish.sh` (+ `publish.conf.example`), `scripts/release.sh`, `MANIFEST.in`.
- `readme.md` renamed to `README.md`; usage section rewritten for Linux.
- Fixed: `python -m build` failed because the sdist lacked the readme and requirements (this also
  affected the GitHub publish workflow); `--makeConfig` template referenced a git-ignored image list.

## Behaviour changes

- `--makeConfig` always exits after running (before, it continued into a normal run when the file existed).
- Logs go to `./logs/` in the folder you run from.
- `--config` defaults to `None` (was `False`); the default file is still `config.yml`.
- Exit codes: 0 on success, 1 on config errors.
- Internal function signatures changed (anything importing `pixBoards` internals must pass `config`).

## Verification

Smoke-tested in a scratch folder (Python 3.14, no PostgreSQL):

- `--help` works without a config; missing and empty configs give clear errors (exit 1).
- `--makeConfig` twice: second run leaves the edited file alone.
- Nested folders with `--recent 10 --random 3`: correct tree, pages and index. `--recent` order
  is newest first, including a filename with a space.
- `--imageLists` and `--dir` runs.
- `--gitPush` twice to a local bare repo: init/commit/push work; an old token embedded in the
  remote URL is removed; no token in `.git/` or logs. The credential helper returns the right
  username/password through `git credential fill`.
- Hash map: `create_html_file` puts the hash (not the URL) in the page.
- Random Page JS (run in node): never returns the current page, URL-encodes names, only shown on multi-page boards.
- Wheel built and installed: `pixboards` console script works, pages show version 1.0.1, metadata lists the right dependencies.

**Not tested:** `--upload`, `--saveBoards`, `--sidecar`, `--useSaved` against a real PostgreSQL
database and imgchest; visual rendering of the new button in a browser.

## Second pass (all selected task bundles)

Implemented after the cleanup pass: upload/DB bugs, `--recent`/`--reddit`, pagination and
escaping, performance, the justified layout, the "broken now" fixes, interaction, index and
loading improvements, code cleanup, renames, `pyproject.toml` with extras, and tests + CI.
Personal configs were moved to `archive/configs/`; only `config_example.yml` remains.

### Design changes
- **`MediaItem`** (`pixBoards/media.py`): every board holds a list of items (`src`, local `path`,
  `hash`, `width`, `height`, `timestamp`). This replaces the parallel `image_paths` /
  `img_filenames` / `link_hash_map` lists that got out of sync.
- **Local media cache** (`pixBoards/mediacache.py`): SQLite at `~/.cache/pixboards/media.sqlite3`
  keyed by path and trusted while size and mtime are unchanged. It stores MD5, image size and
  timestamp, and fills them in a thread pool.
- **Rendering** (`pixBoards/create.py`): one Jinja `Environment` with autoescaping. Pagination,
  breadcrumbs and the index tree are template code now; `styles.css` and `script.js` are static
  files (settings travel as CSS variables and `data-` attributes). `filemaking.py` was merged in.
- **Upload path** (`pixBoards/imgchest.py`): small SQL helpers (`lookup_links`, `save_link`,
  `backfill_filenames`, `ensure_cache_table`) built with `psycopg2.sql.Identifier`. One lookup per
  folder; each upload committed straight away; errors roll back and the folder is skipped.
- **Classes**: `Board` / `Page`; `page.board`; `Board.paginate(per_page, padding, paginate)`.
  `paginate: False` in the config now really puts a board on one page.
- **Packaging**: `pyproject.toml` (dynamic version from `pixBoards.__version__`); base
  dependencies Jinja2, Pillow, PyYAML; `[upload]` adds psycopg2-binary, requests, python-dotenv;
  `[test]` adds pytest. `setup.py`, `MANIFEST.in`, `requirements.txt` and
  `pixBoards/templates/__init__.py` were removed.

### Fixed along the way
- EXIF dates were never found: the old code searched the top-level EXIF tags, but
  `DateTimeOriginal` lives in the Exif sub-IFD. (Pinterest images carry no EXIF at all, so for them
  the file time is still used.)
- `create_index_file` ignored its `template_path` argument (gone with the rewrite).
- `server_port` in the config was never used; it is now passed to PostgreSQL. `sslmode` is supported.
- `row_height` in your configs was ignored (the code read `height`); both names work now.
- The `--makeConfig` template referred to a git-ignored image list and Windows paths.
- `--ranDir` was removed: it was documented but never did anything.
- The JSON dump (`json_dump: true`) writes one `dump.json` for all boards; before, each board
  overwrote the previous one.

### Behaviour changes
- Upload boards keep the folder's file order (before: sorted by the random part of the imgchest
  link, which was effectively random).
- The skipped-images log is `logs/skipped_images.log`; `desc_images*.log` are no longer written.
- Clicking an image opens the lightbox; Shift+click copies (before: a click copied).
- Video-only folders and HEIC files work as before; HEIC still only displays in Safari.

### Verification
- 39 pytest tests: boards, nesting, pagination, scanning, sorting (EXIF/mtime/reddit),
  config handling, media cache invalidation, rendering and escaping (a filename containing
  `" onerror="…<b>`), the upload path against a fake database (alignment, `--useSaved`,
  sidecar, rollback), and full CLI runs. ruff lint and format are clean.
- Real data: 4,947 files in 61 folders from the provided Pinterest folder (read-only). First run
  6.1 s, repeat run 0.34 s.
- Rendered pages screenshotted in headless Firefox: justified rows flush on both edges with no
  cropping and a left-aligned last row; masonry; index with thumbnails and folders.
- Wheel and sdist built from `pyproject.toml` and passed `twine check`; installed without extras,
  `--upload` reports the missing extra instead of crashing.
- Not tested: a real PostgreSQL/imgchest run, clicking through the lightbox and shortcuts in a
  desktop browser, Python 3.9 (CI covers it).
